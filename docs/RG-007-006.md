## SDK work it needed

Both titles recompile with **no title hints**; `configs/` gains nothing. The
first codegen of each exposed SDK gaps, fixed in ReXGlue:

- **Missed entries**
  ([rexglue-sdk#103](https://github.com/furqanagwan/rexglue-sdk/pull/103)):
  - **The failures:** each title's codegen stopped on one tail branch to code
    that no function covered: Blood Stone `0x8222D588` and Legends `0x826D3F38`.
  - **The boot fatal:** Legends' first boot then stopped on a call to the
    unregistered `0x82225D90`, a one-instruction thunk.
  - **The cause:** gap fill skipped segments that start at, or inside, a
    function already known.
- **Instructions** (same PR):
  - `ldbrx` and `stdbrx`, used at 11 sites in Blood Stone;
  - `vrlb`, used at 51 sites in Legends;
  - `vpkd3d128` float16_4 with pack 3, used in Blood Stone.
- **Window identity**
  ([#102](https://github.com/furqanagwan/rexglue-sdk/pull/102),
  [#104](https://github.com/furqanagwan/rexglue-sdk/pull/104)): the window
  shows the title's own name and dashboard icon. Legends' name is shown
  without its trademark sign.

After these, codegen reports no errors, warnings or unimplemented
instructions:

| Title | Functions |
| --- | --- |
| Blood Stone | 61,782 |
| 007 Legends | 42,469 |

## Not validated

- starting a mission, gameplay and saves;
- input beyond the controller connecting;
- visual accuracy against a real console;
- AMD and Intel GPUs, and the standard (non-GDK) build.

Quantum of Solace was re-run on the same SDK as a regression check. It ran 90
seconds with no error lines and the window title `Quantum of Solace`.

## Extraction

The disc images were extracted with a small XDVDFS reader, not
extract-xiso. It finds the volume descriptor at the XGD2 or XGD3 game
partition offset and copies the files. On the Quantum of Solace disc its file
list and `default.xex` size match the earlier extraction. Any XDVDFS extractor
gives the same files.
