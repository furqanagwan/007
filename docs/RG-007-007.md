# RG-007-007: Quantum of Solace save-and-exit jumps

Issue: [#20](https://github.com/furqanagwan/007/issues/20).
Shared SDK work: [RG-FIX-006 / #107](https://github.com/furqanagwan/rexglue-sdk/issues/107),
[PR #108](https://github.com/furqanagwan/rexglue-sdk/pull/108).

## Trigger and existing fix

The user reported a Quantum of Solace failure on save-and-exit. Opus identified
the engine's error/disconnect path reaching CRT longjmp and added the explicit
`setjmp_address = 0x825ABAE0` and `longjmp_address = 0x825AB7C0` overrides.
Those edits are preserved on `RG-007-007`.

The pinned XEX SHA-256 is
`a96f4f651cc0937e51aa2f81245b48ba08d71de1b8bef0e33bc2b2bca29caa42`,
title `415607FF`, media `06DD88A0`, version 7, no title update.
Ordinary recompiled register restoration cannot return through the correct
native C++ stack. The explicit overrides select the SDK's host-jump path.

## Shared follow-up

The SDK branch now recognizes the complete CRT pair at relocated addresses,
preserves explicit hints and scopes native jump buffers to live callers. It
stores separate guest snapshots for multiple buffers and restores state after
native unwinding. Its synthetic generated PPC tests cover the non-local-return
behavior independently of private game assets.

Private codegen of this Quantum of Solace build, with only the two jump hints
removed from a disposable config, also detected the same pair. The committed
explicit hints remain useful provenance for this pinned title build.

Blood Stone and Legends contain matching routines. That investigation was an
applicability check following Quantum of Solace's failure, **not** a report of
a Blood Stone save/exit crash. Shared discovery belongs in the SDK; do not add
speculative title patches or claim those games' jump paths were exercised.

## Save, exit and load, 2026-09-28

Same executable as the session above, debug log level, the same disposable
user data. The session ran 201 s and exited with code 0; the log has no
errors, and its only warnings are missing language packs.

1. **Load.** At startup the game mounted the save written by the previous
   session six times (21:39:48 to 21:40:02) and resumed from it.
2. **Save.** At 21:42:49 it wrote profile settings and `savegame.svg`
   (301,327 to 410,336 bytes).
3. **Exit.** At 21:42:52 it made the `XGIUserSetContextEx(0, 0x8001, 0)` calls
   that begin leaving the level, then streamed files for about 8 s until the
   window was closed.

Before the fix, six sessions (logs 035 to 044) crashed at step 3: the unhandled
guest read of `0x70172634` in `sub_82299400` came in the same millisecond as
that call, about 3 s after the save. The same sequence now passes.

## Result

Fixed. The explicit hints stay as provenance; the SDK also detects the same
pair without them.

Broader gameplay remains in [#16](https://github.com/furqanagwan/007/issues/16).
Original saves are untouched. NVIDIA is the local validation GPU; AMD/Intel
graphics are unavailable and non-blocking.
