# RG-007-004: recurring missing indirect guest entries

Tested XEX: title `415607FF`, media `06DD88A0`, SHA-256
`a96f4f651cc0937e51aa2f81245b48ba08d71de1b8bef0e33bc2b2bca29caa42`.

The first observed target, `0x824E1710`, was absent from the generated registry.
A title-scoped entry hint generated its intact PPC body: it checks a guest
object pointer, returns zero when absent, and otherwise follows the original
virtual call. Codegen and the private Release title build succeeded. Two
NVIDIA D3D12 boot runs with separate disposable user roots passed this former
fatal and both reached a new unregistered target, `0x824BFD00`. Both exited
`0xC0000409`; executable SHA-256 was
`b1a816dde53e74b4fa61375401b9054f300f9e21abed262ca9c49976e214ad53`.
Private run manifests: `Quantum of Solace/baseline/rg007004-boot-{1,2}/run.json`;
title logs: `quantumofsolace_025.log` and `quantumofsolace_026.log`.

The next target, `0x824BFD00`, also generated a valid guest body: it follows
object pointers and tail-calls the original virtual method. A second hint
registered it. Two more NVIDIA D3D12 runs passed that former fatal, then both
stopped at `0x82462650` with the same `0xC0000409` exit. Their executable
SHA-256 was `08e746fac7b285945364166da91a52f0137ed7952771d793db3258af92bf2153`.
Private manifests: `rg007004-two-boot-{1,2}/run.json`; title logs:
`quantumofsolace_027.log` and `quantumofsolace_028.log`.

The next target, `0x82462650`, generated a valid guest body that follows an
object pointer and tail-calls its virtual method. With that title hint, two
more NVIDIA D3D12 runs passed the former fatal and both stopped at a new
unregistered target, `0x82485D08` (`0xC0000409`). Executable SHA-256:
`3da69e2529419640b099621d60dbb9f8a40e85cba2c2f0df2a97ca7b703d6037`.
Private manifests: `rg007004-three-boot-{1,2}/run.json`; title logs:
`quantumofsolace_029.log` and `quantumofsolace_030.log`.

A debug codegen pass reported zero RTTI Complete Object Locators in this XEX;
the SDK's current vtable scanner therefore adds no entries via that path.
The wider discovery investigation is
[rexglue-sdk#32](https://github.com/furqanagwan/rexglue-sdk/issues/32).

The next target, `0x82485D08`, appears in a `.rdata` pointer run at
`0x82097E8C` beside registered methods. Its generated PPC body is a short
argument adapter and tail call, so an exact title hint was added. Two more
NVIDIA D3D12 runs passed that address and both reached a new unregistered
target, `0x8246F540`, after about nine seconds (`0xC0000409`). Executable
SHA-256: `a0db0a4ae2f986aa39391bb4819ca9d242185bdb13fe3402dc9bcfd469736bbd`.
Private manifests: `rg007004-four-boot-{1,2}/run.json`; title logs:
`quantumofsolace_031.log` and `quantumofsolace_032.log`.

The next target, `0x8246F540`, generated a valid guest leaf body that writes
two fields and returns. With its exact title hint, one NVIDIA D3D12 run reached
the 45-second capture timeout without a fatal log; a second run exited
`0xC0000409` after 23.8 seconds at a new unregistered target, `0x82120C00`.
Both repeatedly attempted to open the relative path `scaleform\\`, which
exists under the extracted private game root, but VFS reported no matching
device for the unqualified guest path. This may be a distinct filesystem
resolution defect; its cause is not yet proven. Executable SHA-256:
`0cc1feb151f150016aac9d10c2ad19bb4e262da47c0544273ab1ab662995fdf0`.
Private manifests: `rg007004-five-boot-{1,2}/run.json`; title logs:
`quantumofsolace_033.log` and `quantumofsolace_034.log`. The two outcomes
are not equivalent and neither is a compatibility pass.

A temporary, uncommitted SDK experiment mapped only `scaleform\\` to the
game drive. Two private NVIDIA runs then had no `scaleform` open failures but
both still exited `0xC0000409` at `0x82120C00`. The experiment was reverted
and the private runtime DLL restored. Relative path semantics remain under
investigation in
[rexglue-sdk#34](https://github.com/furqanagwan/rexglue-sdk/issues/34);
this path failure is not the immediate dispatcher fatal.

The next guest target, `0x82120C00`, is a short pointer-adjusting thunk to
another registered guest function. An exact title hint registered its original
body. Two NVIDIA D3D12 runs with separate user roots passed the former fatal
and both stopped at a new unregistered target, `0x8233A678`, after 20–24
seconds (`0xC0000409`). Executable SHA-256:
`9cbfd1d172389b90c644ac708eb18a691ac0796b8af723393ce692f3cdfc8a63`.
Private manifests: `rg007004-six-boot-{1,2}/run.json`; title logs:
`quantumofsolace_038.log` and `quantumofsolace_039.log`.

The next target, `0x8233A678`, generated a valid virtual-dispatch thunk.
Two NVIDIA D3D12 runs passed its former fatal, but diverged. One exited with
an access violation (`0xC0000005`) after 19.5 seconds. Windows Application
Event 1000 identifies `rexruntime.dll` at offset `0x115051`; disassembly
places that instruction in `std::vector<rex::input::DeviceInfo>::clear()`,
while reading a string allocation pointer. This identifies the fault site,
not the underlying cause. The second run exited `0xC0000409` after 20.8
seconds at a new unregistered guest target, `0x8233A688`. The two runs used
the same executable SHA-256:
`cad169033c47bbb4299baa1bfb72801ca7fa45d64910c50dbbb299fd16c9d53b`.
Private manifests: `rg007004-seven-boot-{1,2}/run.json`; title logs:
`quantumofsolace_040.log` and `quantumofsolace_041.log`. This hint remains
under test; the access violation needs independent investigation before merge.

The SDK input refresh race was fixed in
[rexglue-sdk#36](https://github.com/furqanagwan/rexglue-sdk/pull/36).
Two more NVIDIA D3D12 runs using that rebuilt runtime both passed
`0x8233A678` and stopped at `0x8233A688` after about 19–21 seconds,
without repeating the host access violation. Private manifests:
`rgfix004-boot-{2,3}/run.json`; title logs: `quantumofsolace_042.log`
and `quantumofsolace_043.log`. The private title executable was unchanged
(SHA-256 `cad169033c47bbb4299baa1bfb72801ca7fa45d64910c50dbbb299fd16c9d53b`).
The limited run count cannot establish that every host crash is fixed.

The adjacent target `0x8233A688` generated another valid virtual-dispatch
thunk, which loads the method at offset 88 rather than 84. With its exact
title hint, two NVIDIA D3D12 runs reproducibly exited `0xC000001D` after
about four seconds. Both Windows Application Event 1000 reports identified
the same title EXE offset `0x1A31326`. The map placed the trap in generated
`sub_821C1B90`: its jump-table switch used guest `r9` (the constant table
base) instead of the index from `r3`. Private manifests:
`rg007004-eight-boot-{1,2}/run.json`; title logs:
`quantumofsolace_044.log` and `quantumofsolace_045.log`. Executable SHA-256:
`f0dd68ab7c1b126f8fc3589ee7a44e78fad5fc5da2683a1490bcc050f1351b31`.

The SDK fix in [rexglue-sdk#38](https://github.com/furqanagwan/rexglue-sdk/pull/38)
keeps the correctly discovered jump table during emission. Forced title
regeneration changed this switch to `ctx.r3.u32`. Two more NVIDIA D3D12 runs
passed the former trap and both reached a new unregistered guest target,
`0x8233ADD0`, after about 19–21 seconds (`0xC0000409`). Private manifests:
`rgfix005-boot-{1,2}/run.json`; title logs: `quantumofsolace_046.log`
and `quantumofsolace_047.log`; executable SHA-256:
`8db5cef3fffc9e9495434c92f828d1a491666201862097b5e387c72f3386363b`.

The next observed target, `0x8233ADD0`, has an intact PPC body that selects
a floating-point value from the guest object. An exact title hint registered
it. Early attempts were invalid as fix validation: the title CMake
build invoked the older installed `rexglue.exe`, which regenerated the
incorrect `r9` jump-table switch, and the title directory still contained
the older `rexruntime.dll`. One run reached `0x823B8370`; another reproduced
the earlier input-device access violation. Private manifests:
`rg007004-nine-boot-1/run.json` and `rg007004-ten-boot-{1,2}/run.json`.

After updating the installed SDK generator and runtime from their tested
Release builds, forced codegen restored the `r3` switch. The title used
runtime SHA-256 `73a635a90a76d85e8f386ccc7a593b904e2d8bde633f41547de8ad9e14119f7f`.
Two NVIDIA D3D12 runs then both passed `0x8233ADD0` and stopped at the
next unregistered guest target, `0x823B8370`, after 38.9 and 41.5 seconds
(`0xC0000409`). Private manifests: `rg007004-eleven-boot-{1,2}/run.json`;
title logs: `quantumofsolace_051.log` and `quantumofsolace_052.log`;
executable SHA-256:
`e81aa513320d3f4b0c8465e1562653b1195db0316dc1957f2e00d41f69d03327`.

The next target, `0x823B8370`, is a two-instruction PPC pointer-adjusting
thunk (`addi r3,r3,48; blr`). With its exact title hint, two NVIDIA D3D12
runs reached the full 45-second capture timeout without a fatal log. The
process remained active; this is not a boot or rendering pass. Both logs
still contain repeated failures to resolve the relative guest path
`scaleform\\`. Private manifests: `rg007004-twelve-boot-{1,2}/run.json`;
title logs: `quantumofsolace_053.log` and `quantumofsolace_054.log`;
executable SHA-256:
`0c57de49535d76537998ab8020174a256543219b1cb8233c242c05768dffb054`.

The SDK relative-path fix in
[rexglue-sdk#39](https://github.com/furqanagwan/rexglue-sdk/pull/39)
resolved the repeated `scaleform\\` failure for unqualified ObDosDevices
opens. Two NVIDIA D3D12 captures with the candidate behavior and one with
the final SDK build each ran to the 45-second timeout without a
`scaleform` or fatal log line. The title executable was unchanged;
the final runtime DLL SHA-256 was
`775f1b412151eeab810156dcde88d8d11b55d3c9abd4a17c2622208f4aac89d4`.
Private manifests: `rgfix003-boot-{2,3,4}/run.json`; final title log:
`quantumofsolace_058.log`. These observations do not establish rendering,
gameplay or a compatibility pass.

A subsequent interactive-window observation used the same title executable
and final SDK runtime. The title remained active from 13:42 through at least
13:44 local time without a fatal log. Private window crops
`rg007004-window-visual-{1,2,3,4,5}.png` show changing outdoor 3D camera
views with sky, trees and buildings at 1280x720. The process was then
stopped for the investigation. This verifies visible, advancing rendering
through the early scene. Controller response, menus, playable interaction,
visual accuracy and saving have not yet been assessed.

Repeated missing indirect targets across unrelated code regions may indicate
a wider discovery gap. This is a hypothesis, not a diagnosed SDK defect. Trace
the pointer source and candidate function before extending the title hint or
changing the SDK. Early 3D rendering is verified on NVIDIA; gameplay, save,
visual accuracy and GDK compatibility are not. AMD and Intel graphics remain
untested.
