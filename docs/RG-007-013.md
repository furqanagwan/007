# RG-007-013: One folder per game, with its own README and configuration

The root README now says only which games are recompiled, where releases will
be, and how to play. Each game's folder holds its own `README.md` and codegen
configuration:

| Game | Folder | Configuration |
| --- | --- | --- |
| Quantum of Solace | `Quantum of Solace/` | `quantumofsolace.toml` (was `configs/quantumofsolace.toml`) |
| Blood Stone | `Blood Stone/` | `bloodstone.toml` (new; no settings yet) |
| 007 Legends | `Legends/` | `legends.toml` (was `configs/legends.toml`) |

- `configs/quantumofsolace-60fps.toml` is removed. It only set "Unlock FPS"
  on at first start; the patch is in `quantumofsolace.toml`, switchable in the
  guide's Settings > Patches. A build that used it starts with the patch off,
  unless the player's saved choice (`code_patch_states`) turns it on.
- Each game page collates its details from the
  [LaunchBox Games Database](https://gamesdb.launchbox-app.com/) (release
  dates, developers, players, rating) and
  [x360db](https://github.com/xenia-manager/x360db) (marketplace description,
  banner), and the release identity from the disc and XEX headers. Where they
  differ, the more specific source is used: x360db gives Quantum of Solace's
  release date as `2008-01-01`, a placeholder; LaunchBox gives 4 November 2008.
- The banners are linked from x360db and not stored here.
- Build steps moved to [building.md](building.md); manifests now include
  `../<game>.toml`.
- `docs/RG-007-012.md`, linked before but missed by the allowlist, is now
  tracked.

Statuses are unchanged: Blood Stone and 007 Legends stay **Investigating**
until a record shows play past the front end.
